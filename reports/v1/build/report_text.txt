Abstract
We study supervised estimation of the matter-density parameter Ωm and
fluctuation-amplitude parameter σ8 from CAMELS IllustrisTNG total-matter maps at
redshift zero. The project compares Ridge regression and a multilayer perceptron (MLP) on
50-bin projected power spectra with convolutional neural networks (CNNs) on full 256 × 256
density maps. Simulation-level partitioning keeps each simulation’s 15 related maps together
across training, validation, and test groups. The three disjoint dataset levels contain 67, 333,
and 600 simulations. Ridge and MLP tests show moderate gains over a training-mean
baseline, with weak small-sample performance for σ8. On the level-3 held-out test set of 120
simulations and 1,800 maps, the 10-step CNN obtains map RMSE (0.0211, 0.0304) and the
16-step CNN obtains (0.0192, 0.0324) for (Ωm, σ8). Averaging predictions within each
simulation improves these errors further, though the two CNNs retain different strengths.
Saved Gaussian-noise experiments show larger group-average errors at noise strength 0.05
than at 0.01. Because those experiments use corrupted training and test inputs, different
shortlisted models, and validation-selected checkpoints, they do not establish the benefit of
training-time augmentation on clean data. Complete score tables, all saved figures, and a
source manifest accompany this report.

1
Introduction and research questions
The project asks how well simulated matter-density fields constrain two cosmological parameters,
and how performance changes when the input is compressed into a power spectrum. CAMELS
was designed to support joint studies of cosmology and astrophysics with varied simulation
parameters [1, 2]. Here, Ωm denotes the present-day matter-density fraction, and σ8 is the
amplitude of linear matter fluctuations on the conventional 8 h−1 Mpc scale. The task is
supervised point prediction within the IllustrisTNG Latin-hypercube (LH) dataset.
Three comparisons guide the analysis. First, does a nonlinear MLP improve on a regularized
linear predictor when both receive the same 50 spectral features? Second, how much predictive
accuracy is obtained by giving a CNN access to the full spatial field? Third, what do the saved
noise experiments reveal about performance on corrupted maps? The final comparison uses the
same level-3 test simulations for all four principal models. Results from other levels and the
complete validation search remain part of the record, rather than being replaced by the best final
result.
The repository README describes an earlier preprocessing-only scope. This report follows the
merged implementation and saved model outputs, which also include training and evaluation.
The relevant local evidence is identified throughout and frozen under sources/; its original
repository paths and SHA-256 hashes are listed in source_manifest.json [4].
2
Dataset and preprocessing
2.1
Source data and targets
The configured input is Maps_Mtot_IllustrisTNG_LH_z=0.00.npy, paired with
params_LH_IllustrisTNG.txt. The project uses 1,000 LH simulations and 15,000 total-matter
maps. Each map has 2562 pixels and spans a periodic square of side 25 h−1 Mpc at z = 0; these
geometric properties match the CMD documentation [3]. Fifteen consecutive maps belong to one
simulation, so map index i is associated with parameter row ⌊i/15⌋in the project’s loader.
The first two columns of the parameter file provide Ωm and σ8. Four additional supernova and
active-galactic-nucleus feedback parameters are retained as metadata, but are not regression
targets. The learned mapping therefore operates across the astrophysical variations present in
this dataset. This should not be interpreted as a demonstration of transfer to observations or to
a different hydrodynamical simulator.
2.2
Simulation-grouped partitioning
camels_pipeline/splits.py shuffles simulation IDs with seed 42, partitions them into three
disjoint levels, and assigns complete simulations to a held-out test group and five development
folds. It audits overlap both within and across levels. The counts in Table 1 follow the actual
split contract, which rounds the requested map counts to whole simulations.

The test groups contain 13, 67, and 120 simulations, respectively. Splitting individual maps at
random would allow related views of the same simulated universe to appear on both sides of
evaluation. The grouped scheme avoids that failure. Because the levels are disjoint rather than
nested, their score differences combine changes in sample size with changes in the actual
cosmologies assigned to training and test sets. Plots against development size are descriptive
comparisons, not a controlled learning-curve experiment.

The DC mode is excluded. Fifty fixed linear radial bins run from 2π/L through the axis Nyquist

Paired map and spectrum exports contain labels, simulation IDs, map IDs, and manifests. The
software checks row alignment and simulation isolation. Those implementation checks establish
the intended data handling; they do not independently reproduce every historical model run
summarized here.
2.4
CNN input transformation
CNN inputs use log10 max(ρ, 10−5), followed by one global training-set mean and standard
deviation over all training pixels. The resulting tensor has shape (M, 1, 256, 256). During
validation search, these statistics are fitted using folds 1–4 and reused for fold 5. During final
clean CNN training, the statistics are refitted using all five development folds and stored with the
checkpoint. CNN targets remain in their original units.

3.2
Multilayer perceptron
The spectral MLP has two ReLU hidden layers and a linear two-output layer. The original and
stronger-decay configurations use 50 →32 →16 →2 (2,194 trainable parameters); the larger
configuration uses 50 →64 →32 →2 (5,410 parameters). Both features and targets are
standardized using training data only. Reported physical-unit predictions invert the target
standardization.
All three configurations use AdamW with learning rate 10−3, batch size 64, and a maximum of
20 development epochs. The original and larger networks use weight decay 10−4; stronger decay
uses 10−2. Weight initialization and the comparison batch-order generator use seed 42. The best
validation-MSE epoch is retained within each fold.

3.3
CNN architecture search and final models
The registry contains 40 CNN variants: five variants each at step labels 4, 6, 8, and 10, six at
labels 12 and 14, and eight at label 16. These numbers are the authors’ operation-step labels,
which count activations and pooling as well as learned operations; they are not counts of
convolutional layers. The two tagged clean searches each contain 20 models at level 1, ten at level
2, and five at level 3. The level runner ranks the previous level before selecting the next shortlist.
The validation training code uses folds 1–4 for training and fold 5 for validation, MSE averaged
across the two unscaled targets, AdamW at learning rate 3 × 10−4 and weight decay 10−4, batch
size 32, gradient clipping at norm 1, and cosine annealing toward 10−5 over 25 epochs. The
minimum validation-MSE checkpoint is saved. This is a single validation fold, rather than the
five-fold protocol used for Ridge and MLP.
The final clean comparison fixes model_10_5 and model_16_5, the level-3 winners of the two
tagged searches, and trains each for 25 epochs on all 7,200 development maps. The final epoch is
retained without validation selection. Their structures are:
• CNN-10: three 3 × 3 convolutional blocks with 64, 128, and 256 output channels and
LeakyReLU activations. Two 4 × 4 max-pooling operations are followed by adaptive
average pooling to 2 × 2 and a linear 1024 →2 head.
• CNN-16: five convolutions with output channels 32, 64, 128, 128, and 128, using kernel
sizes 5, 5, 7, 3, and 3. The network includes two batch-normalization layers, LeakyReLU,
two 4 × 4 max-pooling operations, adaptive average pooling to 2 × 2, and a 512 →32 →2
head.
The final checkpoint payload includes preprocessing statistics, training simulation IDs, settings,
and target means. The test notebook checks that those training IDs do not overlap its test IDs.

3.4
Gaussian-noise experiments
For map ρm, the saved augmentation code constructs
eρm(x) = max(0, ρm(x) + αsmϵm(x)) ,
ϵm(x) ∼N(0, 1),
(5)
where sm is the spatial standard deviation of that raw map. The noise strengths are α = 0.01
and 0.05. The transform preserves float32 shape and labels, and clips negative densities before
the CNN logarithm. It creates one deterministic corrupted copy of each map; it does not expand
the number of training examples or sample fresh noise every epoch.
The generator visits every maps.npy leaf, including test leaves, and initializes the same random
seed for each leaf. Consequently, these experiments evaluate networks trained and tested at the
matching corruption setting. Reusing the seed can repeat corresponding noise patterns across
equal-shaped leaves and merits revision in a future robustness study. Metadata and manifests are
copied from the clean data rather than updated with a new corruption provenance record.
The noise test notebook evaluates five shortlisted checkpoints per group: step labels 4–10 (group
1) and 12–16 (group 2). It computes the arithmetic mean of the five separate model MAEs and
RMSEs. It does not average predictions into an ensemble. Preprocessing statistics use folds 1–4,
consistent with the saved validation-selected checkpoints; unlike the final clean CNNs, these
models are not refitted on all five development folds. Model membership also changes between
noise settings. These distinctions limit direct comparisons with the clean final test.

6.3
Simulation averaging and interpretation
Simulation averaging reduces CNN-10 RMSE to (0.0111, 0.0161) and CNN-16 RMSE to
(0.0106, 0.0245). CNN-16 retains the best Ωm score, but CNN-10 is clearly better in the recorded
σ8 result. The CNN-16 σ8 error falls by less under averaging than the CNN-10 error. This is
compatible with residual errors shared across views, but the saved aggregate scores alone do not
identify their physical cause.
The result is consistent with useful information being retained by the spatial representation and
learned CNN mapping beyond what these 50-bin spectral regressors extract. It does not isolate a
uniquely non-Gaussian physical statistic: input representation, network class, parameter count,
optimization, and model-selection procedure all differ. The single-seed CNN outcomes also do
not establish that deeper architectures universally improve inference. The target-specific winners
show why one should avoid declaring a single architecture best on every criterion.

Limitations and next experiments
8.1
Statistical and scientific limits
The principal CNN test results come from one seed and one held-out level-3 split after selection
on a single validation fold. No repeated-seed variance, simulation-bootstrap confidence intervals,
or significance tests are saved. The small test group at level 1 and the disjoint construction of the
levels constrain how precisely learning trends can be inferred. MLP cross-validation standard
deviations describe development-fold variability, not uncertainty in the final test ranking.
Fifteen correlated maps from the same simulation provide different views, not 15 independent
cosmologies. Simulation averaging is useful but presumes access to multiple views at inference.
The study is restricted to one field, one redshift, and one simulation suite. It does not evaluate
transfer to SIMBA, observational masks, resolution changes, instrumental systematics, posterior
calibration, or predictive uncertainty. Consequently, the report claims point-prediction accuracy
within the supplied simulated test distribution, not a measurement of the cosmological
parameters of the real Universe.
8.2
Reproducibility and artifact limits
Historical shared CNN files do not include the settings and provenance needed to reconcile their
differences with tagged runs. The original preliminary MLP notebook also has a different
batch-order history from the later configuration search. These are preserved as separate evidence,
not treated as exact repetitions. The clean final test CSV and the separately saved MLP JSON
differ only at small numerical precision: for example, level-3 Ωm MLP map RMSE is
0.0896231222 in the common CSV versus 0.0896231011 in its own JSON. Both round to the same
values used in this report.
Final MLP JSONs identify checkpoint paths and hashes. Those particular MLP checkpoints are
not part of the tracked result set included in this report; the report preserves their metadata and
predictions, not a claim that every model can be rerun from this folder alone. The included clean
CNN checkpoints in the repository are also not duplicated into the report package. The saved
augmentation manifests lack explicit noise provenance, and the repeated leaf seed should be
addressed before a controlled robustness experiment.
8.3
Prioritized follow-up
The most useful next steps are repeated-seed and simulation-bootstrap comparisons of the two
selected CNNs; matched five-fold selection across model families; nested training subsets with a
common untouched test set; and a fixed-model clean/noisy evaluation matrix. A stronger
spectral baseline or alternative statistics could clarify how much of the CNN advantage comes
from information beyond the present compression. Cross-suite testing and calibrated uncertainty
estimates would be needed before broader scientific inference claims.
9
Conclusion
The saved project results show that both spectral baselines learn some cosmological signal, but
their improvements are moderate and σ8 inference is weak in the smallest dataset. On the
common clean level-3 test, CNNs yield much lower map and simulation errors. CNN-16 leads for
Ωm while CNN-10 leads for σ8, so the recorded evidence favors target-specific assessment over a
universal depth ranking. The noise study records worse group-average performance under
stronger corruption, while leaving training-time augmentation benefits unresolved. This report
